<objective>
Close three of the six 2026-08-12 security-audit findings that are all "wire up
what already exists" fixes in `app/public/encryption.py` and
`app/public/profiles.py`: give `encrypt_share` the owner-or-delete-token
authorization check it's missing (SEC-01), give `reencrypt_share` the same
password-guess rate limiting `unlock_share` already has (SEC-02), and fix the
one-character `NameError` bug that makes `GET /api/u/{username}` return 500 on
every call (SEC-06).

Purpose: these are three of the CRITICAL/HIGH findings from the audit report
(`plans/reports/security-audit-260812-1452-public-endpoint-auth-ratelimit-report.md`)
that are currently live and exploitable over the Cloudflare Tunnel. All three
reuse a pattern that already exists correctly elsewhere in this codebase — no
refactor, no new abstraction, no new library.

Output: `encrypt_share` requires an owner JWT or matching `delete_token`;
`reencrypt_share` is rate-limited before it touches storage; `GET
/api/u/{username}` returns a real 200/404 response. Two new test files
(`tests/test_profiles.py`, `tests/test_rate_limit_boundaries.py`) plus three
new tests in `tests/test_all_endpoints.py`.

Assumption-delta check (already resolved, not re-litigated): the deterministic
scanner flagged the word "another" in SEC-01's requirement text as a possible
singular→plural identity-model change. This was manually assessed as a false
positive — SEC-01 is a same-user-vs-different-user authorization boundary
(who owns this one share), not the introduction of a second kind of any
concept. Disposition: no-change.
</objective>
